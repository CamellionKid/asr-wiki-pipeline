# Interview Q&A Extract

把清洗后的面试转写切成可追溯的问答对。**一问一答是 ASR 的完整转写重排，不是摘要**：除题干标题与清单外，所有问答正文必须逐句保留清洗稿原文。本 Skill 只负责切分与结构化，不评价答案、不推断动机、不写岗位画像。

## 完整转写原则（最高优先级）

1. **问题原文**与**回答原文**逐句保留清洗稿，不允许压缩复述、不允许概括成要点、不允许「大意是」。
2. 长回答按语义分段，每句都必须来自原文；可以删除的仅有：纯填充词（「那个」「嗯」）、无语义重复。删除后不改变任何信息。
3. 只有三处允许压缩：题干标题（≤40 字）、问答清单、说话人表「依据」列。
4. 完整性三条同时满足才算通过（字数比 >100% 是重复信号，不是通过信号）：
   - 句级覆盖：清洗稿正文每个 ≥12 字的句子都能在 01 中找到 ≥ 90%。
   - 无重复：同一题的「问题原文」与「回答原文」不得包含相同段落；全文引用重复率 ≤ 5%。
   - 无占位：不得残留 `〔…〕`、TODO、待补。
5. 面试官的完整提问过程（含铺垫、自我纠正、追问）同样逐句保留；候选人的回答不截断、不省略「跑题段」。

## 输入

按优先级取一份清洗稿：

1. 调用方传入的 `cleaned_text_path` 或 pipeline manifest 中的路径
2. 用户点名的 Obsidian 笔记（`obsidian read`）
3. 对话中已经是清洗稿的正文（先写入 `/tmp/asr-interview/intake/` 再处理）

若文本仍含大量填充词、重复段、语言错检，先停并路由到 `asr-cleaner`（只清洗、不归档）。不要边清洗边拆问答。

同时读取（若存在）：`company`、`position`、`round`、`record_date`、`interview_role`（self / observer）、`pipeline_id`、`raw_note` 双链。缺字段时用 `[U]`，不要编造。

## 输出

一份 `01 <活动名>｜一问一答.md`（NN 序号 + 活动名前缀，见 asr-pipeline 命名规则）。由 `asr-pipeline` 写入 52 Wiki 面试包时沿用该命名；独立调用时写到用户指定位置，未指定则先给预览再问落点。

格式见 [references/qa-format.md](references/qa-format.md)。读取该文件后再写正文。

## 工作流

1. 通读清洗稿，列出说话人标签、时间戳样式、明显的面试官/候选人角色。
2. 按说话人轮换切问答对。连续追问并入同一题的「追问」列表，不拆成假新题；每次追问的原文也完整保留。
3. 无法配对的独白、寒暄、环境说明标为 `[U]` 或「非问答片段」，**保留完整原文**，不丢弃。
4. 保留时间戳、`[名词待确认]`、`[lang-mismatch]` 等上游标记；不静默改专有名词。
5. 给每题一个稳定编号 `Q01`、`Q02`…；标题用面试官问题的压缩句，不超过 40 字（压缩仅限标题）。
6. 把每题的问题原文、追问原文、回答原文从清洗稿**整段搬入**，按上面完整转写原则处理。
7. 跑完整性自检（句级覆盖 ≥ 90%、无重复、无占位），不通过则补齐。
8. 写 YAML：`type: interview-qa`、`source` 指向 Raw / 清洗稿、`pipeline_id`、`company`、`position`、`round`。
9. 独立调用且用户要求写入 Vault 时，用 `obsidian` CLI 创建笔记；被 `asr-pipeline` 调用时只返回正文与建议文件名，由主 Skill 落盘。

## 切分规则

- 面试官提问 + 候选人作答 = 一对。
- 面试官在答案中途插话澄清：并入该题的「追问」，不要新开题号。
- 候选人反问、面试官回答：单独成对，并在 `turn_type` 标 `candidate-question`。
- 多人面试官轮流问：在该题标注 `interviewer` 说话人标签。
- 自我介绍、收尾寒暄也保留为问答对，不要当噪声删掉。

## 停止条件

- 输入是原始嘈杂 ASR：转 `asr-cleaner`。
- 说话人标签缺失且无法从内容判断角色：先问用户，或把双方标为 Speaker N + `[U]`。
- 含候选人/员工可识别个人信息且用户未确认归档：输出中保留，但提醒调用方标记 `sensitive_data`。
