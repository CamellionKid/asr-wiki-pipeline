# 用户画像与系统记忆查询指南

通过**系统级 `AGENTS.md` / `agent.md`、MCP 长期记忆及用户画像**加载上下文背景，生成专有名词纠错候选字典。背景与画像仅作为 ASR 音译与专有名词的纠错候选，不是录音事实来源；只有发音、上下文和时间线共同支持时才可用于修复。

---

## 2. 查询策略与执行细节

### 层级 1：系统级 / 工作区 `AGENTS.md` / `agent.md`

在执行前优先检查当前系统环境或工作区中的 Agent 记忆与规范文件：
- `~/AGENTS.md` 或 `./AGENTS.md`（系统级全局 Agent 协议与个人概况）
- `DARREN THE NOTES/- Agent Relate/AGENTS.md`（Vault 级记忆上下文）

**提取要点**：
- **用户基础画像**：姓名（如 Darren）、核心角色（HRBP、AI 转型等）、工作所在地
- **组织与业务**：当前所属公司（如 库犸科技 / Mammotion）、核心产品线（如 割草机器人、充电基站等）
- **高频专有名词**：内部常用缩写（如 HRBP、COE、SSC、IPD、OD 等）

---

### 层级 2：MCP 长期记忆与用户画像检索 (`claude-mem` / `mcp-search`)

若当前环境已注册 MCP 记忆工具（如 `claude-mem` 或 `mcp-search`），通过 memory 工具执行画像与长期记忆检索。

#### 1. 必查画像与组织上下文（每次执行）

使用 `observation_context` / `memory_search` / `memory_context` 检索：

| 检索维度 | 查询关键词推荐 | 用途 |
|---|---|---|
| **用户画像与身份** | `user profile identity background Darren` | 确认用户人设、表达习惯、核心业务域 |
| **公司与业务上下文** | `company work context business product lines Mammotion` | 公司全称、产品代号、业务专业术语 |
| **团队与高频人际** | `colleagues team members contacts key stakeholders` | 同事/合作伙伴姓名拼写，辅助说话人与人名识别 |

#### 2. 按需领域检索（根据转写内容命中触发）

| 录音中出现的信号 | 追加查询关键词 |
|---|---|
| 涉及面试、薪酬、招聘沟通 | `recruitment hiring candidates HRBP interview` |
| 涉及具体技术、算法、硬件开发 | `product engineering technical terms hardware architecture` |
| 涉及市场、竞品、行业动态 | `market intelligence competitors industry insights` |

#### 3. MCP 调用参数规范

```text
MCP Server: claude-mem (或 mcp-search)
Tool: observation_context / memory_search
Arguments:
  query: "<查询关键词>"
  limit: 10
```

## 3. 返回结果使用与字典构建

从 `AGENTS.md` 及 MCP 返回的 `context` / `observations` 中提取实体，构建**专有名词修复候选字典**：

```json
{
  "酷马": "库犸",
  "库马科技": "库犸科技",
  "mammoth": "Mammotion",
  "motion": "Mammotion",
  "割草机": "割草机器人",
  "HRB P": "HRBP",
  "三支柱": "HR三支柱"
}
```

### 实体校验与修复阶梯
1. **高置信度（完全对齐）**：发音与上下文高度吻合（如「酷马」在讨论割草机器人公司时），直接替换为「库犸」。
2. **中置信度（近似推测）**：替换并在报告中记录：`[推测修复: 原文 → 修复]`。
3. **低置信度（模糊可疑）**：保留原文并显式标注：`[名词待确认: 原文]`。

---

## 4. 认识论与安全约束

1. **纠错候选 $\neq$ 事实依据**：记忆与用户画像仅用于修正 ASR 的音近错字与拼写错误，**严禁**将记忆中存在但录音中未提到的事实补写进清洗稿。
2. **说话人非推定原则**：同事名单与画像只辅助辨别姓名发音，不能仅凭记忆中存在某人就将“说话人不明”强行标注为该人。
3. **隐私防护**：若长期记忆或录音涉及敏感员工信息/候选人隐私，需在清洗 manifest 中正确标记 `sensitive_data`。

---

## 5. 降级策略 (Graceful Degradation)

当 `AGENTS.md` 不存在或 MCP 记忆服务不可用（未注册/超时/无结果）时：
1. **不阻塞主工作流**：跳过背景注入，正常执行 7 类纯文本去噪。
2. **保守保留专有名词**：对所有疑似专有名词与拼写异常标注 `[名词待确认: 原文]`。
3. **报告显式记录**：在 `cleaning-report.md` 的降级信息中注明：`⚠️ 系统记忆/用户画像未加载，专有名词修复采用降级模式`。
