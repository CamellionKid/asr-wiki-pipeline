# ASR 清洗规则

按 7 类噪声逐项处理。每类标注处理方式和判断标准。

## 目录

- [清洗不变量](#清洗不变量)

## 清洗不变量

1. **原始来源不可变**：不要覆盖媒体、provider transcript 或用户粘贴的原文。
2. **清洗不是摘要**：只修复可识别的转写问题，不压缩观点、删除有效事实或生成分类结论。
3. **不确定性可追溯**：所有低置信度名词、说话人、语言错检和损坏片段都保留显式标记，并汇总到清洗报告。
4. **时间证据优先**：保留 provider 时间戳；没有时间戳时只能使用文本中可确认的时段，不自行补时间。
5. **缺席不等于否定**：录音“未提到”的信息不能改写成“没有”或“不存在”。

## 1. 重复转写 (Duplicate Segments)

**识别信号**：连续出现语义相同或高度相似的段落（ASR 引擎对同一音频片段重复输出）。

**处理**：
- 合并为一份，保留语义最完整的版本
- 如两段互补（各包含对方缺失的信息），合并为一段
- 在报告中记录合并位置；不要删除只出现一次的有效细节

**示例**：
```
原文：「那个就是说我们公司的产品线。我们公司的产品线主要是做割草机器人。」
清洗：「我们公司的产品线主要是做割草机器人。」
```

## 2. 错误语言检测 (Language Mismatch)

**识别信号**：中文语音被转为英文/日文/韩文等非目标语言的文字。

**处理**：
- 标记 `[lang-mismatch: 原文]`，不强行翻译
- 如能根据上下文确定原意，在标记旁附推测：`[lang-mismatch: "xxx" → 推测：yyy]`
- 典型场景：中英混杂录音中，短语被错识别为另一语言

## 3. 专有名词错识别 (Proper Noun Errors)

**识别信号**：公司名、产品名、人名、技术术语被错误音译或拆分。

**处理**：
- 用用户画像与系统记忆上下文（Step 1 加载）中的已知专有名词进行匹配修复
- **高置信度修复**（记忆/画像中有完全匹配）：直接替换
- **中置信度修复**（记忆/画像中有近似匹配）：替换并标注 `[推测修复: 原文 → 修复]`
- **不确定**：保留原文并标注 `[名词待确认: 原文]`
- 候选字典只提供纠错参考；若发音、上下文或时间线不支持，不得因记忆中存在该实体而强行替换

**常见模式**：
- 「库犸」←→「酷马」「库马」（公司名）
- 「Mammotion」←→「mammoth」「motion」
- 「HRBP」←→「HR BP」「HRB P」

## 4. 说话人混杂 (Speaker Overlap)

**识别信号**：多人对话中未标注说话人；或同一段混合了不同人的发言。

**处理**：
- 如能从语境/人称判断说话人，标注 `[说话人: 推测姓名/角色]`
- 不确定时保留原文，标注 `[说话人不明]`
- 不虚构说话人身份
- 系统记忆/画像中的同事名单不能单独证明说话人身份

## 5. 环境噪声片段 (Environmental Noise)

**识别信号**：ASR 将背景音、音乐、通知声等非人声转为文字。

**处理**：
- 识别特征：无意义词汇堆砌、与前后文无语义关联
- 从清洗稿正文移除噪声片段，但原始 transcript 保持不变
- 在原位留标记：`[环境噪声已移除: 时间戳/片段号]`
- 无法区分环境噪声与低置信度人声时，保留并标注 `[疑似环境噪声]`

## 6. 断句错误 (Segmentation Errors)

**识别信号**：一句完整的话被拆成多段；或多句话被合为一段。

**处理**：
- 基于语义和标点恢复正确分句
- 保留原始时间戳标记（如有）
- 不改变原意

## 7. 填充词与口头禅 (Filler Words)

**识别信号**：「嗯」「那个」「就是说」「然后呢」等口头填充词。

**处理**：
- **适度清理**：移除不影响语义的填充词
- **保留语气线索**：当填充词反映犹豫、思考、情绪时保留
- **保留连接功能**：「然后」在叙述时间线时保留
- 不把口语表达改写成更强、更确定或更正式的判断

**示例**：
```
原文：「嗯那个就是说我觉得嗯这个候选人的话呢嗯他其实还是蛮不错的。」
清洗：「我觉得这个候选人其实还是蛮不错的。」

原文：「嗯……我不太确定这个决定是不是对的。」
清洗：「嗯……我不太确定这个决定是不是对的。」（保留：反映犹豫）
```

## 清洗输出格式

清洗完成后输出两个独立文件，并把路径写入 handoff manifest。不要把清洗稿错误地称为“ChatGPT 一级压缩”。

### 1. `cleaned-transcript.md`

去噪后的完整转录，保留时间戳、说话人标记和所有待确认项。推荐结构：

```markdown
# 清洗后转录

## [时间段或时间戳] · [主题占位，可省略]

[说话人标记（如有）] 忠实清洗后的正文。
```

主题只用于导航，不得把下游分类或新结论写回正文。

### 2. `cleaning-report.md`

```markdown
**ASR 清洗摘要**
- 输入类型：音频 / 视频 / 原始转录
- ASR 质量：N / 无 provider 评分
- 原始字数：N
- 清洗后字数：N（字数保留率 XX%）
- 噪声分布：
  - 重复转写：N 处
  - 语言错检：N 处
  - 名词修复：N 处（其中推测修复 N 处）
  - 环境噪声：N 处
  - 断句修复：N 处
  - 填充词移除：N 处
- 待确认项：N 处
- 分类候选：动作层 / 判断层 / 背景层 / 元层（仅提示）
- 降级信息：系统记忆/用户画像未加载 / 无时间戳 / 其他
```

把待确认项逐条列出并尽量附时间戳。`asr-life-log` 只消费此报告，不重新计算或重复清洗。
