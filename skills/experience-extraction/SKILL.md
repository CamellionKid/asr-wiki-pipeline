# Experience Extraction

把一场面试或一次分享里真正可迁移的做法抽成**详细** Wiki 知识卡片。三层结构：忠于原文的转译层、上升方法的提炼层、外部专业信源的补充层。上升方法必须标明 `[M]`，不能改写成当场已经采用的做法；外部补充必须给可点开的来源。

## 加载参考

写卡片前读完 [references/extraction-methods.md](references/extraction-methods.md)（卡片模板、信源清单、检索协议都在里面）。

## 输入

按优先级：

1. `01 一问一答.md` 或会议 `01 …｜一问一答.md` / `01 …｜全文转写.md`（须为完整转写版）。被 `asr-pipeline` 调用时从 `pipeline.json` 的 `qa_path` 读取，不要从纪要或横向分析代替原文。
2. 会议再读横向分析 + 分享纪要（用来定主题，不代替 01 原文）
3. 已有的逐题评分 / 面试官分析 / 现场问答索引（用来定位高信号，不代替原文）
4. 清洗稿（面试无问答时先调用 `interview-qa-extract`；会议无 01 时先调用 `talk-share-extract`）

建议字段：`domain`（HR / AI / Market Intelligence / 其他）、`company`、`position`、`pipeline_id`。

## 输出

`04 <活动名>｜经验萃取.md`（面试包）或 `06 <活动名>｜经验萃取.md`（会议包；NN 序号 + 活动名前缀，见 asr-pipeline 命名规则）：

1. 知识卡片总览表（知识点 / 一句话 / 使用场景）
2. 逐卡展开：场景、原文转译、提炼、**外部补充**、使用场景、边界、双链
3. 与既有 Wiki 概念的双链

被 `asr-pipeline` 调用时，主 Skill 负责按 knowledge-compiler 规范补 `source_id`、登记 Raw↔Wiki、Daily Log。独立调用时至少写好 `source` 双链和 `origin_type: interview-analysis`。

## 工作流

### 1. 从原文收候选

只从高信号问答收点：对方追问加深的、自己讲出了可复述步骤的、或明确失败/改口的。每张卡片必须能指回至少一处时间戳或题号。

**会议/黑客松模式（输入是 01 原文 + 横向分析时）**：不按作品出卡，按**主题**出卡——转译层的原话必须能指回 01 的题号或场次，不要只引用纪要摘要。

- 卡片数 3±1，每张卡对应横向分析里一个已升级的主题，禁止「一个作品一句话」的碎卡。
- 每张卡的证据必须覆盖 ≥2 个独立场次（跨作品互证）；只有单一场次支撑的亮点留在纪要里，不进萃取。
- 例外：用户点名或证据强度显著高于全场的单个项目，可以单独立卡，但必须在卡内声明「单点证据」并写清为什么它值得例外。
- 卡片排序即主题权重：第一张卡放全场最厚、证据最多的主题。

### 2. 三层书写

- **转译层**：用面试/分享原话说明当时怎么做、做到哪、权限是什么。标记 `[F-S]`。
- **提炼层**：第一性原理、领域工作流、或可复用检查清单。标记 `[M]`，并写适用边界。
- **外部补充层**：专业信源里的框架、实证或反例。标记来源 URL + as-of 日期。

不要把提炼层写进转译层；不要把外部补充写成当事人当场做的事。

### 3. 外部研究（每张卡片必做，不是按需）

每张卡片至少一个外部锚点。检索顺序：

1. Vault 内 `obsidian search` 已有概念卡与摘要
2. **学术 / 期刊层**：Google Scholar、期刊论文（HR 如 JAP / HRMJ / Personnel Psychology；AI 如 arXiv / NeurIPS / Anthropic 与 OpenAI 研究博客）
3. **权威行业信源**：HBR、MIT Sloan Management Review、SHRM、ATD、Gartner；AI 领域官方文档与工程博客
4. **开源实现**：GitHub `topic:` 检索，优先 README 含可运行步骤的仓库，参考 `borghei/claude-skills`（面试 loop 与评分 rubric）、`hsuanlolo/interview-feedback-copilot`（逐字引用核验）这类结构

来源分级：期刊论文 > 行业研究 > 权威媒体 > 厂商博客 > 个人博客。低分级来源要标注。

每个外部锚点记录：框架名、URL、`(as of YYYY-MM, source)`、为什么比原话更可执行、它不能替代原文的部分。找不到就写「未检索到更合适的外部框架」，**不要编造作者、年份或 URL**。

### 4. 双链

能链到已有概念卡就链，例如 `[[HR-001 HRBP（人力资源业务伙伴）]]`。不要为了双链而新建空概念卡，除非用户要求编译。

## 卡片质量门槛

一张卡片必须同时满足：

- 有原文锚点（题号/时间戳）
- 有可执行的下一步或机制，不只是态度句
- 有至少一个外部锚点（或明确的「未检索到」声明）
- 有「什么时候不能用」

态度、鸡汤、纯公司内部八卦不入库。卡片正文要有实质内容：六段式写全，不接受一句话卡片。

## 停止条件

材料不足以支持任何可复用卡片时，输出「本场无可沉淀卡片」加原因，不要硬凑十张表。
