# 一面 / 二面对照报告

## YAML

```yaml
title: "<公司> <岗位>｜一面二面对照"
date: YYYY-MM-DD
type: interview-round-compare
company:
position:
rounds: [一面, 二面]
sources:
  - "[[一面文档地图或分析笔记]]"
  - "[[二面文档地图或分析笔记]]"
status: consistent | partial | conflicting | incomplete
```

`status: incomplete` 用于缺轮次。此时不要填一致性矩阵里的空造数据。

## 正文模板

```markdown
# <公司> <岗位>｜一面二面对照

> [!abstract] 结论
> 同一张岗位画像能否继续使用：能 / 需校准 / 不能。一句话说明最大分歧。

## 一、检索结果

| --- | --- | --- | --- |

## 二、一致性矩阵

| 维度 | 一面 | 二面 | 判定 |
| --- | --- | --- | --- |
| 工作内容 | | | 一致 / 部分一致 / 不一致 / 一轮缺失 |
| 能力要求 | | | |
| 服务项目 | | | |
| 组织阶段与约束 | | | |
| 决策变量（留任/薪酬/工具/编制等） | | | |

判定列可用加粗标出「不一致」。不要用 HTML 颜色。

## 三、差异摘要

对每一条「不一致」或「部分一致」：

1. 一面原话 + 定位
2. 二面原话 + 定位
3. 更像是考察切片不同，还是岗位定义真的变了 `[I-H/M/L]`
4. 建议核实对象（一面面试官 / 二面面试官 / 用人经理 / JD）

## 四、行动

- 若一致：可继续用同一份画像准备或招人
- 若冲突：列出 1–3 个必须当面问清的问题
```

## 判定标准

- **一致**：两轮描述可并存，只是粒度不同（一面说招聘，二面展开为需求澄清 + 渠道）
- **部分一致**：重叠但重心已迁移（一面招聘为首，二面说招聘不急、重心在任职资格）
- **不一致**：直接打架（一面要能独立建任职资格，二面只要执行考勤档案；或服务项目完全不同）
- **一轮缺失**：不打分，不做假一致
