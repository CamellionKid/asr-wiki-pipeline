## 评价基准

不采纳面试官自己的评价，只看：**实际经历 × 回答质量 × 岗位要求**。

- 面试官的口头表扬、热情、岗位介绍长度是「推进概率」的数据点，不是答题质量的证据。
- 面试官透露的更高预期（「接班人」「平等对话的助手」）另立第二评分标准，做双标准对照，不混入名义标准。
- 面试官框架里的前提先检验再使用（例：「非科班 = 缺口」「盘点 = 强制分布」「都基于冰山模型」）。

## 分制

- 题分：**1–5 分**，允许 0.25 步进（如 3.5、4.25）。
- 总评：**100 分制加权维度表**为主（见下）；不再用题分均分映射当总评。

## 回答状态档

清单表的「回答状态」由题分映射：

| 题分 | 状态 |
| --- | --- |
| ≥ 4.25 | 较好（可成招牌答案） |
| 3.75–4.25 | 较好 |
| 3.25–3.75 | 中上 |
| 2.75–3.25 | 中等 |
| 2.25–2.75 | 中等偏弱 |
| < 2.25 | 偏弱 |
| 全场最低且是关键题 | 本场最大 Gap |

## 每题必写字段

清单表内每题一行：`# | 面试问题 | 实际考察点 | 回答状态 | 题分`。

深度分析按主题块写，块内引用题号。块内每题或每个论点需要时展开：

```markdown
**考察目标（likely）**：一句话，说明这题大概在验证什么。

**实际回答**：关键原句和时间戳 `[F-S]`（完整原文在 01 一问一答，此处只引关键句）。

**做得好**：可被面试官直接用的信号。

**缺口**：缺证据、缺方法名、缺结果、缺权责、接不住场景压力。

**分数**：X / 5  
**证据状态**：shown / partly shown / to verify

**可改口结构**（可选）：结论先行 → 场景变量 → 方法 → 交付物 → 边界。
```

## 1–5 锚点

| 分 | 含义 | 典型证据 |
| --- | --- | --- |
| 1 | 未接题或答非所问 | 跑题、空泛态度、把问题推回给面试官 |
| 2 | 有经历切片，无方法或无权责 | 「协助过」「参与过」，讲不出自己做了哪一步 |
| 3 | 能讲清做过什么，方法偏通用 | 有案例但套教科书；场景变量（样本少、无预算、无工具）未进入推理 |
| 4 | 方法匹配场景，有交付物或可复核结果 | 讲得出标准/流程/取舍；能说明自己的权限边界 |
| 5 | 在该组织阶段可直接上手 | 小样本、粗放期、无工具等约束下仍有可执行路径，且与对方真实任务咬合 |

0.5 分用于「方向对但关键牌没打出来」（例如手里有 0-1 手搓经历却只回「没问题」）。

## 加权维度表

总评用 100 分制，5–8 个维度按岗位定制。示例（TD 设计向岗位）：

| 维度 | 权重 | 得分 | 判断 |
| --- | --: | --: | --- |
| 相关经历真实性与丰富度 | 20 | | 带证据 |
| 核心专业知识 | 20 | | 概念是否成体系 |
| 方案设计 / Ownership | 15 | | 执行者 vs 设计者 |
| 业务与战略意识 | 15 | | |
| 系统整合能力 | 15 | | 模块能否连成闭环 |
| 反思与迁移能力 | 10 | | |
| 专业表达精确性 | 5 | | 术语检索、结论前置 |
| **总分** | **100** | | 一句话定档 |

规则：

- 权重合计必须 100；改默认维度要写明理由。
- 「判断」列必须有证据或缺口描述，不接受空泛形容词。
- 表后必须附「为什么只有 X 分而不是 Y」：把能力按 强 / 中 / 未被证明 三档列清，说明分数卡在哪。
- 双标准对照（面试官透露高预期时）：名义岗位标准 X vs 高预期标准 Y → 综合 Z，并解释两个分数各自意味什么。

## 反向挑战

打完分、写完块分析后，必须跑一次 challenge：

1. 哪些加分其实证据不足（只靠自述、无交付物）？
2. 哪些扣分其实不公平（问题本身超纲、面试官已诱导）？
3. 哪些结论是从面试官框架继承的，没有独立验证？
4. 如果换一个立场相反的评审，会攻击这份评分表的哪三处？

挑战结果写进报告（可并入「最终判断」或单列小节），发现失衡就改分并说明。

## 禁止项

- 用面试官「很专业」「很认可」代替答题质量
- 把未出现的模块写成「没有该能力」；应写成「本场未展示」
- 把 `[U]` 项纳入扣分主因
- 用后来补学的 SDT、MVQ、KSAO 等改写为「当时已经这样答了」；这些标 `[M]`
- 对同一答案做多版同义润色；若给替代路线，必须换因果起点或决策逻辑
- 把面试官的隐含前提当评分标准（如「接受尾部淘汰 = 成熟」）；先检验该前提
- 只写「面试官喜欢什么」的迎合版复盘；分歧点必须保留候选人更专业的回答版本
