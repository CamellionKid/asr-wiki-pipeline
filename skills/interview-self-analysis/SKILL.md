# Interview Self Analysis

把 Darren 作为候选人的一场面试，变成一份不迎合面试官评价的深度复盘。基准线：**不采纳面试官自己的评价，只看实际经历、回答质量与岗位要求**。面试官的口头认可是数据点，不是证据。

默认用子代理并行分析；Task 工具不可用时降级为单代理，并在输出里声明。

## 加载参考

- 每次评分前读完 [references/scoring-rubric.md](references/scoring-rubric.md)
- 派子代理或写多视角评估前读完 [references/perspective-playbooks.md](references/perspective-playbooks.md)
- 证据标记沿用 `[F-S]` / `[F-V]` / `[I-H/M/L]` / `[M]` / `[U]`；不要把 ASR 猜测当事实

## 输入

必需：`01 一问一答.md` 路径，或 pipeline 中的 `qa_path`。一问一答必须是完整转写版（见 `interview-qa-extract` 完整转写原则）；若发现问答正文被压缩过，先要求重出完整版，否则深度分析没有原料。

若只有清洗稿、没有问答文件，先调用 `interview-qa-extract`，再继续。不要在本 Skill 里重做 ASR 清洗。

建议字段：`company`、`position`、`round`、`pipeline_id`、Raw 双链。

## 输出

1. `02 <活动名>｜逐题评分.md`：深度复盘主报告，结构固定为十三节（见下）
2. `03 <活动名>｜多视角评估（SSC·BP·COE）.md`：总评仪表盘、跨视角红旗、面试官需求解码

被 `asr-pipeline` 调用时返回正文；独立调用且用户要求写入 Vault 时用 `obsidian` CLI。

## 主报告十三节结构

`02 逐题评分.md` 按以下顺序写，节名可微调但环节不可缺：

1. **评价基准与核心判断**：开头声明按什么标准评（岗位名义要求；若面试官透露了更高预期如「接班人」，另立第二标准）。核心判断用 blockquote：一句话能力结构定位（例如「Project Operator → Method Owner 过渡期」）+ 最大的那个断层是什么。
2. **整场问答清单**：表 `# | 面试问题 | 实际考察点 | 回答状态 | 题分`。回答状态用锚点档（较好 / 中上 / 中等 / 中等偏弱 / 偏弱 / 本场最大 Gap）。
3. **逐块深度分析**：按主题块组织（一块可跨多题，如「胜任力模型」「人才盘点」「任职资格」），不按题号流水账。每块含：
   - 答得好的地方（带时间戳证据）
   - 核心问题：概念错误、逻辑漏洞、专业判断失误（如把高潜当高绩效、把 KPI 当客观、把强制分布当盘点前提）
   - 更专业的完整框架：如果重答，完整的步骤链 / 方法论，写到可直接演练的颗粒度
   - 与面试官的分歧（如有）：不迎合，给出更成熟的回答版本
4. **反向纠正隐含假设**：既纠候选人的错误前提，也纠面试官框架里未被检验的前提（如「非科班 = 缺口」「都必须基于冰山模型」）。每条：原命题 → 为什么不成立 → 更准确的命题。
5. **已实际使用但未命名的方法论**：把回答里的做法翻译成专业方法名（如 BEI / Critical Incident → Coding → Dictionary → SME Review → Criterion Validation），指出「用了但没说出口」的断链。
6. **缺失的总图**：把本场涉及的模块画成一张系统图（text 或 mermaid），指出候选人脑中是「文件夹式模块」还是「操作系统式闭环」。
7. **对方真正测试的顾虑点**：编号列出，每条判定成立度（成立 / 部分成立 / 不太成立 / 无法判断）+ 理由。只当测试假设，不接受面试官结论。
8. **表达层面问题**：口语冗余、结论后置、术语检索失败。用 Concept → Terminology → Framework → Retrieval 定位断在哪一环。给一套统一表达结构（如四句式：结论 → 实际职责 → 问题 → 若我主导）。
9. **加权评分表**：`维度 | 权重 | 得分 | 判断`，100 分制，5–8 个维度按岗位定制，权重合计 100，判断列必须带证据。附「为什么只有 X 分而不是 Y」：把能力强 / 中 / 未被证明三档列清。
10. **双标准对照**（面试官透露更高预期时）：名义岗位标准 X 分 vs 高预期标准 Y 分 → 综合 Z。
11. **岗位真实画像与风险**：从面试官陈述解码这个岗位到底要什么；高承诺低成本等风险点要写出来；列下一轮要确认的问题清单。
12. **下一轮最应强化的表达**：给可直接演练的话术段落，不是建议清单。
13. **最终判断**：推进概率与其证据（时长、对方主动给的信息、下一步安排）；面试官可能的内心判断标 `[I-M]`；最后给候选人要反问自己的尖锐问题。

## 工作流

### 1. 读问答，建证据账本

对每题记下：题干、时间戳、实际回答、直接证据、缺口、可能的考察目标（用「likely」，不断言面试官内心）。同时把题目聚成 3–6 个主题块，供第 3 节用。

### 2. 逐题打分 + 逐块分析

按 scoring-rubric 的 1–5 锚点打题分，写入清单表。深度分析按块写。打分后跑一次**反向挑战**（rubric 里的 challenge 节）：哪些加分证据不足、哪些扣分不公平、哪些结论是从面试官框架继承的。

### 3. 派出三个子代理

并行启动三个独立子代理，最小继承上下文，只传：问答文件路径、岗位名、本场已知组织阶段、对应 playbook 要点。

| 子代理 | 视角 | 产出 |
| --- | --- | --- |
| A | SSC 负责人 | 事务/共享服务执行力、无工具手搓、数据与合规 |
| B | HRBP 总监 | 业务理解、需求澄清、非职权影响力、冲突与留任 |
| C | COE 负责人 | 内部再拆 TD / OD / LD / OC 四块，分别给分与红旗 |

子代理必须：只引用带定位的原文；未知标 `[U]`；不把沉默写成「没有该能力」；不把面试官陈述当成已审计的公司事实。

### 4. 主线汇总

加权默认：SSC 20% · HRBP 30% · COE 50%（COE 内 TD/LD/OD/OC 权重见 playbook，可按岗位改，改了要写明）。

`03 多视角评估` 必须包含：

- 总评仪表盘（各视角分数 + 一句话）
- 跨视角红旗（至少两个子代理独立收敛的同一风险）
- 面试官画像与需求解码表（陈述 → 背后需求，带时间戳）
- 本场真正的决策变量（专业度之外还在看什么）

## 保护规则

- 不覆盖 Raw 或清洗稿
- 不从缺席证据推断动机、身份或录用结果；未考察的能力写「本场未展示」，不写「没有该能力」
- 不把事后学到的方法改写成当场已经使用；事后补充标 `[M]`
- 不声称子代理核验了它未读到的材料
- 不把面试官的框架当默认前提（例如「哲学 = 非科班 = 劣势」）；先检验再使用
- 含敏感个人数据时，未获确认不得把可识别信息写入可复用示例或外部服务

## 停止条件

问答文件不存在、问答正文是压缩版、岗位未知且会改变权重、或用户要求对照一面二面（改走 `interview-round-compare`）时先停下来问。
