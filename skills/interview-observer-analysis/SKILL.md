# Interview Observer Analysis

分析对象是面试官的问题结构与岗位信号，不是给候选人打「录用/淘汰」结论。默认产出一份 `02 面试官分析.md`。

## 加载参考

写正文前读完 [references/observer-framework.md](references/observer-framework.md)。

## 输入

必需：

- `01 一问一答.md`（没有则先调用 `interview-qa-extract`）
- `position` 岗位名称（没有则先问用户，不要用 JD 猜测代替）

建议：`company`、`round`、`pipeline_id`、Raw 双链。

旁观材料常含候选人个人信息。未获用户明确归档确认前：可分析，但 Wiki 落盘时对姓名、学校、前雇主联系方式做最小化处理（保留角色与能力证据即可）。

## 输出

`02 面试官分析.md`，四个固定板块，缺一不可：

1. 面试官提问着重点
2. 对候选人满意的点（必须引原文 + 时间戳）
3. 本岗位目前缺的能力、以及要服务的项目（岗位画像）
4. 候选人提问 / 面试官回答带来的岗位认知增量

YAML 必须带 `company`、`position`、`round`、`interview_role: observer`，供 `interview-round-compare` 检索。

## 工作流

1. 从问答统计题型分布（经历核验、场景压力、价值观、反问、后勤约束）。
2. 把面试官后半段的「自述岗位」单独抽成需求解码表。
3. 满意点只收录面试官明确说出或可高信心推断的信号；推断标 `[I-H/M/L]`。
4. 岗位画像写成「工作内容 / 能力要求 / 服务项目」三列，供后续一面二面对照。
5. 候选人反问单独成节：问题、面试官原答、我们新获得的岗位信息。

不要替面试官做录用决策。不要把候选人未展示写成「候选人没有该能力」。

## 停止条件

岗位名未定时先问。用户要对照多轮面试时改走 `interview-round-compare`。
